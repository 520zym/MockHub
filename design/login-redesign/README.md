# MockHub 登录页重设计 · 三个方向

> 状态：设计稿，仅用于选型。  
> 未修改 `frontend/src/views/Login.vue`，当前登录页保持原样。  
> 日期：2026-11-23

## 出发点

现有登录页是「左侧品牌介绍 + 右侧登录卡片」的双栏结构，方向本身没问题；问题主要是：

- 左侧信息偏满，品牌感和产品价值不够聚焦；
- 右侧登录卡片较普通，缺少“内网工具”的可信感；
- 不同屏幕下左右两块的视觉权重不容易稳定；
- 首次登录改密、错误提示等状态还没有被纳入整体构图。

以下三个方向都保留现有账号密码流程，不引入第三方登录，不展示真实凭证，只调整视觉与信息层级。

本轮已把文字压到最低：每个方向只保留标题、表单标签、按钮和一句必要的首次登录提示；说明性段落、功能清单和装饰性文案全部去掉，改用自绘 SVG 图示：方向 A 是请求 → 匹配 → 响应，方向 B 是环形节点，方向 C 是控制台拓扑。动画参考现有登录页的 LoginMotion，纯 SVG + CSS，不依赖图片或脚本。

## 方向 A：工作台入口

文件：[01-workbench.html](01-workbench.html)  
关键词：品牌叙事、产品预览、平衡

- 左侧浅蓝灰品牌区，加入真实的 Mock 响应预览卡；
- 右侧白色登录卡，保留双栏结构但降低左侧信息密度；
- 用「接口联调，从一个工作台开始」替代泛化的欢迎文案；
- 适合作为默认方向：保留现有用户习惯，同时让品牌与产品能力更清楚。

适合：希望登录页承担“产品第一印象”的场景。

## 方向 B：专注单卡

文件：[02-focus.html](02-focus.html)  
关键词：极简、快速、低干扰

- 居中单卡，弱化背景，只保留品牌标记、标题、两个输入框和登录按钮；
- 没有大段介绍，打开即登录；
- 适合内网工具的高频使用：用户每天来，不需要每次被“介绍产品”；
- 卡片上方用一条蓝色短线和留白建立节奏，底部只保留内网部署说明。

适合：登录是高频动作、希望页面尽量轻的场景。

## 方向 C：控制台分屏

文件：[03-console.html](03-console.html)  
关键词：控制台、专业、内网可信

- 左侧深色控制台栏，展示产品定位、三条能力和本地运行状态；
- 右侧浅色登录区域，表单卡片带“内网连接”状态；
- 信息层级更接近运维/研发控制台，和 MockHub 的产品气质一致；
- 比 A 更重，但更适合强调“本地部署、可控、可追踪”。

适合：主要用户在运维/研发团队，希望登录页直接传达“内网控制台”的场景。

## 对比

| 维度 | A 工作台入口 | B 专注单卡 | C 控制台分屏 |
| --- | --- | --- | --- |
| 品牌感 | 强 | 弱 | 中强 |
| 登录效率 | 中 | 强 | 中 |
| 信息量 | 中 | 低 | 中高 |
| 与现有页面连续性 | 高 | 中 | 中 |
| 移动端适配 | 双栏折叠 | 天然单列 | 左侧折叠到顶部 |
| 推荐场景 | 默认/对外展示 | 高频内网登录 | 运维/研发控制台 |

## 我的建议

**默认选 A，保留现有双栏习惯，同时把左侧从“说明文字”升级为“产品预览 + 价值点”。**

如果团队更在意每天登录的速度，选 B；如果希望登录页更像一个内网控制台，选 C。

## 设计约束

- 不引入客户名称、域名、接口路径和真实凭证；
- 保留用户名/密码 + 首次登录改密的现有流程；
- 最小字号 11px，正文 12–14px；
- 输入框焦点环必须完整可见，不能贴边被裁切；
- 不依赖外部字体、图片或网络资源，单文件可直接打开；
- 桌面 1440px、平板 768px、手机 390px 下均需可用。
