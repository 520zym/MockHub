# 页面简报（构建契约）

全部页面共享 `assets/desk.css` 与 `assets/desk.js`。画板 1440×900，截图 2x。
**只允许**使用 desk.css 已有的 class 与 token；缺组件时消息通知 Lead，不自行发明颜色/圆角/阴影。
所有数字、账号、Token、日志均为演示数据；不出现真实凭证、不虚构产品未声称的能力。

## 全局内容事实（照抄，别改产品语义）

- 产品：内网接口模拟服务，单个 jar，离线运行。REST + SOAP Mock。
- 团队：交易中台（acme）、会员中心、风控服务。当前团队 = 交易中台。
- Mock 基地址：`http://mockhub.local:8080/t/acme`
- 角色：超级管理员 / 团队管理员 / 普通成员。当前账号：张一鸣 · 超级管理员。
- 导航（超管）：接口 · 文件服务器 · 动态变量 · 使用统计 · 日志记录 ｜ 账号管理 · 团队管理 · 全局设置
- 接口示例（真实字段形态）：
  - GET `/api/order/{orderId}` · 订单详情 · 3 个返回体 · 今日 412 次
  - POST `/api/order/create` · 创建订单 · 2 个返回体 · 今日 268 次
  - PUT `/api/user/{userId}/profile` · 更新资料 · 1 个返回体 · 今日 96 次
  - DELETE `/api/cart/item/{itemId}` · 删除购物车项 · 1 个返回体 · 今日 12 次
  - GET `/api/payment/callback` · 支付回调 · 4 个返回体 · 今日 187 次
  - SOAP `/ws/OrderService` · 订单 WSDL · 3 个 Operation · 今日 39 次
- 返回体条件（条件都是 AND）：
  - Query：`channel = alipay`
  - JSON Body：`amount >= 500`
  - Header：`x-mock-sandbox = 1`
  - SOAP XML Body：`OrderType = refund`
- 兜底：无条件返回体在最后，未命中走它。随机模式：等概率从启用的返回体中抽取。

## 通用硬约束

1. 不用卡片网格当页面结构；面板是纯白实面 + 1px hairline，无阴影、无模糊、无渐变。
2. 圆角只用 `--radius`(2px)；标签可用 `.chip`。不要 12/16px 圆角。
3. 禁止：渐变文字、玻璃拟态、彩色左右粗边框、硬偏移阴影、emoji 或 unicode 图标、牛皮癣式说明文案。
4. 正文最小 12px；11px 只用于表头、角标、kbd、注解。
5. 中文文案；控件命名动作（"复制 cURL" "停用"），错误说明原因与恢复路径。
6. 交互状态至少覆盖：hover / focus-visible / disabled 或 empty 之一，并在画板上能看到其中两个。
7. 键盘可达：按钮/链接是真 `<button>`/`<a>`；图标按钮必须有 aria-label；表单有 label。
8. 数字用 `.num`，路径用 `.path`（参数用 `.param`），方法用 `.method`（读=空心灯，写=实心灯，DELETE 加 `--danger`）。
9. 不写 01/02 之类的装饰编号；不写 "在这里你可以…" 的教学文案。
10. 自检：`node build/render.mjs <page-id> --check` 必须全 OK（溢出、阴影、渐变、对比度、极小字号、未命名控件、外部资源、JS 异常）。

## 01 登录（01-login.html）

目标：让人一眼确认这是内网工具、能登录、且它真的在 Mock。

- 版式：左右 55/45。左侧纸色，右上角只有品牌墨块；右侧白面表单，垂直居中，宽 360。
- 左侧内容：`MOCKHUB` 字标 + 一句产品事实（"内网接口模拟 · 单个 jar · 无需外网"）；下面一块 `.code--inv` 的墨色"实时样例"，展示一次请求到返回的 4 行（GET 路径、命中返回体、状态 200、延迟 12ms），像终端而不是装饰图。底部一行小字：版本 1.4.6 · 内网部署。
- 右侧：h1 "登录"；字段 账号 / 密码（密码有显示切换）；"记住此设备" 用 `.checkbox`；主按钮 `.btn--primary .btn--lg` 宽 100% "登录"；下方一条 `.banner--warn` 只在"首次登录需改密"状态下出现——本页显示它，说明会出现。页脚 "忘记密码？联系超级管理员"。
- 状态：给输入框一个 focus-visible 演示（账号框 focus 状态可见），密码框一处 disabled? 不需要。至少显示 banner 与 focus。
- 禁止：大插画、渐变背景、居中卡片浮在渐变上、装饰圆点。

## 03 接口编辑（03-api-edit.html）

目标：在一个屏幕内完成"改这个接口的某个返回体，并立刻验证它会不会被命中"。

- 顶部身份条（白面，下方 hairline）：方法（`.method`）+ 路径（`.path` 中的 {orderId} 高亮）+ 复制地址 + 启用开关 + "未保存修改" 提示（朱红小字）+ 右侧 保存（primary）/ 取消。
- 三栏：左 236（浅纸底）：基础信息（名称/分组/描述/类型 REST·SOAP/标签），字段用 `.field`；底部"危险区"文字按钮"移入回收站"。
- 中：返回体工作区。
  - 标题行："返回体 3 个" + 右侧 添加 / 随机模式开关。
  - 变体列表：每行 44px，含 序号非装饰而是顺序、名称、条件摘要（mono，如 `body.channel = wechat`）、调用占比（mono）、启用开关。第 2 行选中展开。
  - 编辑器：`.code` 内 JSON（带行号），工具栏：格式化 / 插入变量 / AI 生成 / 复制。JSON 用 desk.css 的 .key/.str/.num 着色。
  - 编辑器下：条件区，两条 AND 条件行（来源 select / 字段 / 操作 / 值），加条件按钮，兜底说明。
- 右 320：「试配」面板——请求样例输入（mono，`?channel=wechat` + body 摘要）、"试匹配"按钮、结果块：命中「返回体 2 · 微信渠道」+ 判定链路 3 步（`.chain`，前两步 miss 第三步 hit）+ 状态码/延迟。底部小字："试配为本地演示，真实匹配以服务端为准"。
- 状态：展开行的选中态、保存按钮可用、未保存提示可见。

## 04 请求日志（04-logs.html）

目标：排障时 5 秒内看清"这次请求为什么拿到这个返回"。

- 版式：主从。左 520 列表（白面）+ 上方筛选行（时间范围/方法/状态/搜索，`.search`）；右侧检视器。
- 左侧行：时间（mono 11，如 14:32:07）、方法灯、路径（mono 12，截断）、状态码（200 绿 / 404 灰 / 500 朱红）、延迟（mono，右对齐）。选中行高亮。
- 右侧：请求行摘要（GET … 200 12ms）；`.tabs`：请求 / 响应 / 命中链路（响应为当前）；内容：
  - 请求头表（`.kv` 或两列 mono 表），Query 参数表；Body 用 `.code`。
  - 响应：状态码、Content-Type、字节数、响应体 `.code`。
  - 命中链路：`.chain` 4 步，规则逐条评估 + 命中项，附"重放这次匹配"文字按钮与 AI 诊断入口。
- 也无页脚分页：底部 "共 1,284 条 · 加载更多"。

## 05 使用统计（05-stats.html）

目标：判断哪些接口是活的、哪些该删；不堆装饰图表。

- 顶部 `.stat-row` 四个读数：今日调用 / 成功率 / 走兜底比例 / P95 延迟。每项 label + value(mono 26) + 一行 delta（+8.4% 比昨日）。
- 中：调用趋势（14 天）SVG 折线，只有横向 hairline 网格，墨色线 1.5px，朱红小柱表示失败次数（真实轴标签，11 mono）。图例文字不用色块，用线型说明。
- 下：两栏。左 "调用最多" 表格（接口、方法、次数、占比）；右 "7 天未调用" 表格（接口、最后调用、操作"移入回收站"）。空数据用 `.empty`（画板上展示右侧空态也可以，但两表都要有内容；空态另放一处小注释块）。
- 顶部右侧：时间范围切换（近 7 天 / 近 14 天 / 近 30 天），当前 14 天；导出 CSV 次要按钮。
- 禁止：仪表盘环形图、渐变面积图、hero 大数字卡片墙。

## 06 对话助手（06-assistant.html）

目标：把"问数据/改接口"做成一页可核对的对话，写操作必须落在待确认草稿上。

- 版式：主区对话（最大宽 760）+ 右 300 历史会话（纸底）。
- 对话：用户消息右对齐？不要气泡，用左侧竖线+标签区分（"你" / "MockHub"），更像记录。助手回答里可嵌"数据表"（用 `.table` 紧凑版）与一句结论；再给建议动作（"查看这些接口" 文字按钮）。
- 草稿卡：白面 + hairline 边框，标题"将修改 1 个接口"，diff 行（+ 新增返回体 · 条件 body.channel = wechat；无删除），按钮 确认修改（primary）/ 取消。标注"草稿不会自动写入"。
- 输入区：多行输入 + 快捷提示（"近 7 天调用最多的接口" / "给订单详情加一个微信渠道返回"）+ 发送；下方小字"AI 结果需人工确认 · 当前团队：交易中台"。
- 右侧历史：按日期分组的会话列表，当前高亮。

## 07 团队与成员（07-teams.html）

目标：管理团队与成员，权限一眼可辨。

- 顶部：团队切换列表（三个团队，卡片？不。用表格/列表行），当前团队行选中；右侧"新建团队"。
- 主区：团队详情 = 左侧成员表（姓名、账号、角色、最近活跃、操作），角色用 `.chip` 区分（超管/团队管理员/成员）；右侧团队设置（Mock 前缀、公共响应头、成员上限、危险操作）。
- 内容真实：成员 8 人，其中 1 超管、2 团队管理员、5 成员；邀请成员按钮。
- 状态：一个禁用中的成员行、一个待接受邀请行。
