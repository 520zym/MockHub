# MockHub · 液态玻璃重设计「Liquid Glass Desk」

> 结构按 [pbakaus/impeccable](https://github.com/pbakaus/impeccable) 的判据重排；材质按你的偏好改为**无线框、大圆角、液态玻璃**。
> 本目录是可离线打开的设计稿 + 真实 Chromium 渲染的截图；**没有修改业务前端、没有连接后端**。

---

## 一句话方向

把 MockHub 从「一叠带边框的平铺卡片」改成**浮在柔和网格上的一层玻璃工作台**：状态条、侧栏、面板都取同一套玻璃配方（半透明 + 30px 背景模糊 + 1px 顶部高光 + 22px 圆角 + 大而软的投影），蓝色只表示「当前 / 进行中」，红色只表示破坏性。

## 先看结论：现版本过不了 impeccable 的哪几条

现有界面（含 `design/liquid-glass` 的最终扁平稿）已经把阴影、渐变、玻璃都去掉了，这是对的。但用 impeccable 的判据逐条对，它仍然停在"AI 生成的合格后台"这一档：

| # | 现状 | impeccable 判据 |
|---|---|---|
| 1 | 页面结构 = 白卡片当容器：Stats 四个 KPI 卡、ApiEdit 六张 section 卡、Login 两块 20px 面板 | 卡片是偷懒的容器；嵌套卡片永远错 |
| 2 | `border-radius` 出现 14 种数值，同一张卡在 ≤1200px 还会从 12px 变 16px | 深度只声明一次：边框或阴影；圆角是系统不是散值 |
| 3 | 接口表写死 `min-width:1484px` 塞进 1170px 内容区，靠 sticky 右两列救场 | 真实文案在每个断点跑一遍，别让内容溢出 |
| 4 | 19 种字号，页面标题在 24/25/26/28 之间漂移 | 角色比例要能一眼分辨 |
| 5 | 间距只有 14/20/46 三个数，紧与松没有对比 | 紧组 + 宽分隔；标题上方大于下方 |
| 6 | `tabular-nums` 只挂在 `.app-mono`，命中次数/延迟/占比列不是等宽 | 浏览器替你画的部分也属于设计 |
| 7 | 石墨 `#17191D` 与蓝 `#3568D4` 双主色并存，另有 220 处裸十六进制 | 颜色要带含义；一个色只做一件事 |
| 8 | 24px 实心图标 + 1em 描边图标两套并存，`①②③ ⭐ ✓ ↗ ＋` 当图标 | 图标要画出来，一套描边一套重量 |
| 9 | 条件匹配的因果链被拆进 tab / 折叠面板 / 640px 弹窗三层 | 把产品的核心机制放在同屏 |
| 10 | 运行状态与 Mock 基地址不在全局，行不可聚焦、无键盘路径 | 状态与键盘焦点属于交付底线 |
| 11 | "扁平"只是风格的减法，不是世界的选择 | 重设计要换世界，不是把旧世界磨平 |

逐条证据（文件:行、选择器、实测数值）在 [AUDIT.md](AUDIT.md)。

> 这里不是否定上一版：`liquid-glass` 那版解决了"去装饰"，这版要解决"有自己的结构"，并把材质做回一套有来源的玻璃。
> AUDIT.md 里"14 种圆角 / 220 处裸色"这些判据仍然成立——它们说的是**现状**的问题，不是本案的材质选择。

## 材质配方：只有一套玻璃

| 角色 | 值 | 用法 |
|---|---|---|
| 底色 | 冷调网格 `#F5F8FC → #E3EAF4` + 两团柔光 + 16% 噪点 | 只铺在 body，页面根不再铺色 |
| 玻璃（面板） | `rgba(255,255,255,.66)` + `blur(30px) saturate(1.8)` | 侧栏、表格、检视器、卡片 |
| 玻璃（强调） | `rgba(255,255,255,.86)` | 状态条、当前项、详情面板 |
| 玻璃（浅） | `rgba(255,255,255,.42)` | 卡内分区、左列 |
| 边缘 | 顶部 1px 高光 + 1px 白色外环 | 代替边框；全站没有 >1px 的实线外框 |
| 投影 | 30–80px 大扩散、低透明度 | 只表达层级，不做装饰 |
| 圆角 | 面板 22 / 控件 11 / 标签 7 / 开关药丸 | 三档，不再出现 14 种 |
| 蓝（信号） | `#3568D4` | 当前项、focus、实时流量、选中 |
| 红（破坏） | `#C0443A` | 删除、失败、500 |
| 墨（文字） | `#14181F` / `#3B424D` / `#626C79` | 玻璃上都按合成背景校验过对比度 |

**纪律**：玻璃只用于"面"，不用于"点/线/图标"；一屏最多两层玻璃叠加；不做发光、不做渐变文字、不叠第三种模糊；所有文字都在玻璃之上，且只用墨色三档。

## 结构上的三处真改动

1. **浮起的 54px 状态条**（新）
   团队切换 · Mock 基地址（点击复制）· 实时状态灯（运行中 · 今日 1,284 次）· 助手 · 账号。把"我在哪个团队、地址是什么、服务是否在跑"从页面内部提到全局，任何页面都看得到。

2. **接口列表 → 主从**
   点任意行，右侧 400px 玻璃检视器给出：接口身份、返回体与条件摘要、今日调用、最近一次请求、"复制 cURL / 编辑"。不离开列表就能判断"这个接口还活着吗、该不该删"。勾选走独立状态，底部批量条。

3. **编辑页 → 工作区**
   左 236 基础信息 / 中 返回体变体 + 条件 + 编辑器 / 右 320 **试配**（请求样例 → 逐条判定 → 命中第几条第几条件）。产品的核心机制从"藏在弹窗里的规则"变成同屏可见、可验证。

外加：日志页改为主从（请求 / 响应 / 命中链路三态），统计页用读数行替代指标卡，助手页把写操作固定为"待确认草稿"，团队页把团队 / 成员 / 角色 / 设置放在同屏。

## 一屏的记忆点

接口列表左侧那列 **7px 方法灯**：空心 = 只读（GET/HEAD），实心 = 写入（POST/PUT/PATCH），红色实心 = DELETE；路径里的 `{orderId}` 用蓝色标出。整页读起来像一张接线表，而不是一张卡片清单——玻璃只是把它托起来，不抢信息。

## 验证方式（不是"看起来还行"）

每张画板都用真实 Chromium（headless shell，1440×900 @2x）渲染，并在同一会话里跑一组客观检查，结果写进 [build/audit.json](build/audit.json)：

| 检查项 | 口径 |
|---|---|
| 横向/纵向溢出 | 文档 scrollWidth / scrollHeight 超出视口即失败 |
| 裁切 | 任意可见元素右/左边界越出视口即失败 |
| 对比度 | 逐文本节点算 WCAG 比值：把祖先的半透明背景（含渐变取平均）逐层合成到网格的两种极端底色上，**取更差的那个**；正文 <4.5:1 即失败 |
| 极小字号 | <11px 的可见文本即失败 |
| 控件命名 | button / a / input / select 无 aria/label/text 即失败 |
| 外部资源 | 任何 http(s) 资源即失败（离线铁律） |
| 运行时 | 页面 JS 异常、资源加载失败即失败 |

材质（阴影/模糊/渐变）不再计为失败项——它是本轮的方向；但每页的材质数量会被记录，用来防止"到处 blur"。

最终一版实测（7 页，1440×900，2× 截图）：

- 7/7 页 `OK`，`node build/render.mjs` exit 0；共 1,975 个节点 / 906 个文本节点
- 横向溢出 0、纵向溢出 0、裁切 0、<11px 文本 0、未命名控件 0、外部资源 0、JS 异常 0、对比度失败 0
- 材质用量：每页 8–13 个 `backdrop-filter` 层、17–36 处投影、9–12 处渐变（含噪点与网格底），首页最轻、编辑页最重
- 7 张 PNG 均 2880×1800，1.8–2.3MB（噪点 + 渐变的代价）
- 画板总览 `index.html`：7 张缩略图 2880×1800 全部加载、25 个本地链接全部存在、1440 宽无横溢

## 取舍与已知边界（写清楚比藏起来值钱）

- **玻璃有成本**：每页 8–16 个 `backdrop-filter` 层，低端集显 / 远程桌面下会掉帧。降级方案：检测到不支持时把 `--glass` 换成 `rgba(255,255,255,.9)` 纯色，视觉层级靠阴影保留。
- **Safari 需要 `-webkit-backdrop-filter`**：desk.css 两处都写了；旧版 Firefox 的 blur 会更慢。
- **截图变重**：噪点 + 渐变让 2× PNG 从 ~300KB 涨到 1.5–2MB，适合本地看，不适合塞进聊天工具。
- **玻璃上的文字必须够重**：全站文字只用墨色三档，最小 11px；审查脚本按合成背景算对比度，低于 4.5:1 直接失败。
- **与 impeccable 的一般禁令的冲突**：它默认禁玻璃/发光/渐变。本方向属于"作者授权的材质"——全站只有**一套**配方、不做渐变文字、不做发光、不叠两层以上玻璃，且用脚本证明可读性，因此保留。
- **字体不打包**：离线单 jar 不能引 CDN 字体，正文走系统栈（PingFang / 微软雅黑），数字与路径走系统等宽；跨平台字宽差 3–5%。
- **高密度换来了点击目标偏小**：行 46px、开关 36×20、标签 21px；触摸/200% 缩放下需要把开关与复选框包一层 24px 命中区。
- **1280 以下检视器仍占 360–400px**，列表会被压窄；这是"弹窗换常驻面板"的代价。
- **只证明首屏**：审查脚本证明 1440×900 首屏无溢出、无对比度问题；滚动区深处、真实 Monaco、真实长日志不在证据里。
- **侧栏有四个占位入口**（文件服务器 / 动态变量 / 账号管理 / 全局设置）指向 `#`：它们没有对应画板，不在这 7 页范围内。
- **落地成本**：element-overrides.scss 735 行里大量 Element Plus 覆盖需要重写；玻璃用 CSS 变量 + 一层 `.glass` 工具类即可复用，但 Monaco、ECharts 的内部表面要单独处理（它们不会自动透明）。

## 边界

- 静态设计稿 + 本地状态演示；**不修改业务前端、不连接后端、不写真数据**。
- 所有账号、Token、调用数、日志均为演示数据；不包含真实凭证。
- 未开发移动端；画板只承诺 1440×900 与 1280 以上桌面。
