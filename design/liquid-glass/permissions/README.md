## 已确定的口径

| 项 | 结论 |
| --- | --- |
| 团队归属 | 一人可属于多个团队，角色挂在每条成员关系上（沿用现状 `user_team`），侧栏保留团队切换 |
| 资源归属 | 接口归团队所有；成员离开后接口保留，创建人显示为空 |
| 团队内编辑权 | 只读不能改；可编辑能改团队内全部接口；**不设"仅创建者"开关** |
| 误改兜底 | 创建人列 + 变更记录与回滚 + 软删除回收站 30 天 |
| 两层角色 | 全局 USER / SUPER_ADMIN 与团队角色互不影响 |

## 需要调整什么

| 位置 | 调整 | 原因 |
| --- | --- | --- |
| 公共导航 | 顶部团队切换，显示该团队角色；团队与系统菜单分组 | 同一账号在不同团队角色不同，团队管理员不是超级管理员 |
| 个人入口 | 仍只在左下；资料、安全、会话、我的团队、个人凭证 | 账号身份不随团队切换改变，也不新增右上用户入口 |
| 团队设置 | 团管可管理本团队成员；普通成员只读团队信息 | 把团队自治与全局账号管理分开 |
| 系统管理 | 仅超管有账号管理、团队管理和全局设置入口 | 避免普通团队管理员看到全平台操作 |
| 操作状态 | 只读不显示写操作；可编辑可日常维护；危险操作解释限制 | 不把整个页面变灰，也不让只读开关看起来是接口停用 |
| 生命周期 | 未加入团队、最后管理员保护、停用影响、编辑中降权 | 正常业务状态需要明确反馈，不能靠报错或丢草稿解决 |
| 个人凭证 | 范围、期限、当前权限、实例策略共同约束 | 不能把超管全团队凭证当作普通成员凭证 |

## 不需要重画的部分

接口与匹配规则编辑器、文件预览、变量三栏、统计图表、日志检查器、AI 结果卡及大部分全局设置的**主体信息结构**继续沿用原稿（MCP 的凭证区域除外，需拆成个人凭证与实例策略）；实施时统一接入新的团队上下文、角色化操作与服务端授权。它们的布局不会因为添加只读角色就全部重做。

## 权限与状态语义

- 全局普通用户 / 超级管理员；团队只读 / 可编辑 / 管理员。团队角色不放进系统角色下拉。
- 同一个演示普通账号王琳：PAY 管理员、USER 可编辑、ORDER 只读；系统场景使用超管张一鸣。新账号空状态使用周然。
- 团队资源共享，维护人只是审计信息。移除成员或停用账号都不删除团队资源。
- 活跃团队至少一位有效管理员；系统至少一位有效超管。只有最后一位受保护，不把所有管理员永久锁死。
- 归档团队行为是本稿的额外建议：冻结配置修改，不自动停止已有 Mock 调用；停用接口另行处理。待产品确认后再实施。
- 编辑中降权场景仍保留团队读取权，因此允许复制本地未提交草稿；若被移出团队，应清除团队缓存，不继续展示其他团队数据。
- 账号停用、会话撤销、Token 范围与实时权限收缩均为拟实施规则，静态稿不能证明后端已经实现。
- 个人 MCP 凭证与 Mock 调用 Key、文件上传凭证区分；不在这里新增公开调用策略。

## 预览边界

- 全部为离线 HTML 与本地演示状态，不调用业务 API，不发送邮件，不持久化凭证，不删除真实数据。
- 为避免伪装完整产品，尚未展开的文件/变量/统计/日志/全局设置导航会提示主体沿用原稿。
- 画板内的角色是不同场景的快照，不是可用于真实系统切换身份的权限开关。
- 前端可见性只说明交互设计；真实授权必须由后端校验目标资源团队、当前成员角色和动作。
