## AI 旧历史处理

- 在模型调用前校验请求上下文，在模型选择更新目标后再次按实际 API 团队校验；系统超管也不能绕过当前会话工作区。
- 写入前检查卡片结构与团队；读取已有历史时核对 summary/items 的团队及现存 API/pending action 的真实归属。
- 已混队或无法安全解释的卡片使整段会话隔离：列表不返回标题/preview，详情和续聊拒绝。不只在前端隐藏卡片。
- 不删除、不自动重归属原数据库内容；本人仍能删除该会话。合法旧卡片及正文内业务字段 teamId/apiId 不会被误当授权元数据。

### 共同数据保证

- 原 API ID、正文、SOAP JSON、时间、账号密码哈希、团队与成员关系保持；合法历史角色仅按既定映射规范化。
- 原 REST/SOAP response ID/body/status/delay 保留或正确迁入；已有调用计数、RANDOM、文件服务器下载计数保持。
- pre-V10 每接口只生成一次真实迁移 baseline；V10+ 既有 revision ID/正文不重造。
- 附件与 WSDL 原始字节不变。17 个历史形态还验证旧 WSDL basename 引用可正常托管、地址改写为 Mock 地址、外队同名引用拒绝。
- 旧全量路径唯一索引调整为仅活跃接口唯一；高版本缺统计列的已知形态补齐相应索引。
- 无 sid/auth_version 的旧 JWT 拒绝；无范围旧 MCP 撤销且重启不刷新撤销时间；V8+ 有效既有 session 不任意撤销。

### 不把不安全数据“兼容”为有效权限

- 全局合法值：SUPER_ADMIN、USER，历史 MEMBER/TEAM_ADMIN → USER。
- 团队合法值：TEAM_ADMIN、EDITOR、VIEWER，历史 MEMBER → EDITOR。
- 未知、NULL、空白、错误大小写角色拒绝迁移，报告表/账号/团队/原值；必须由管理员按真实权限修复，不自动映射成 EDITOR 或管理员。
- future schema（含超出 32 位整数范围）拒绝启动，不修改版本记录或 journal_mode。未知未来库和任意损坏库不属于自动修复承诺。
- schema 仍为 V11；无需手工改版本号、清空库或重建业务数据。
