# UI 与权限落地进度

用户于 2026-10-29 授权自主推进全部已讨论功能，并要求按可用功能分批提交；仅本地提交，不主动推送远端。

## 实施基线

- 一人多团队，资源归团队，人走接口留，创建者归因保留。
- 团队 VIEWER / EDITOR / TEAM_ADMIN；旧 MEMBER 迁为 EDITOR，保持既有能力。
- 无资源级“仅创建者”或允许编辑开关。
- 全局 USER / SUPER_ADMIN；超管以显式系统维护身份跨团队，不伪造团队成员角色。
- ACTIVE / DISABLED 账号；JWT 每请求读当前账号/成员事实，认证版本及登录 sid 支持撤销。
- 当前团队由前端按账号和标签页保存，服务端对真实资源团队授权。
- 安全事件（改密、超管重置、停用）撤销网页认证与个人 MCP；普通退出网页不影响 MCP。
- 团队只读可筛选其过去创建的接口；可编辑可修改队友资源。
- 回收站保留 30 天，恢复冲突不覆盖新接口；仅团管/超管可彻底删除；恢复后默认停用。
- 聚合写事务、revision CAS 与文件引用基础先于回收站/历史上线，AI 确认复用同一安全写入。
- 团队归档保留标识并冻结管理写入，不自动中断已有 Mock；停止调用是单独明确操作。
- 正式 Vue 布局采用真正响应式，不沿用静态看稿画板缩放。
- 每个可用功能经过定向与相关回归后独立 commit；不混入运行数据库、缓存或生成的依赖。

## 分批推进

1. 保存当前已认可设计稿与实现方案（静态稿不是业务实现）。
2. 账号/会话基础：V8、status/auth_version/sid、me/profile、会话退出、密码事件撤销。
3. 角色基础与业务权限：V9、统一能力矩阵、只读防写与真实资源团队校验。
4. 团队自治与末位有效管理员保护：所有入口一致且并发安全。
5. 聚合事务、revision、历史快照、文件引用与 AI 确认原子性。
6. 回收站、恢复、彻底删除、历史/回滚界面及清理。
7. 个人 MCP 团队/动作 scope 与实例策略、来源授权复查。
8. 正式 UI：公共主题/图标 → 壳与团队导航 → 列表/编辑 → 团队账号/个人页 → 文件变量/日志统计/设置。
9. 旧库迁移、端到端和全量回归、发布构建；保留分阶段 commit 历史。

## 并行边界

- 账号/会话任务使用独立 worktree，独占 V8 迁移与认证相关文件。
- 公共前端主题任务使用独立 worktree，只改全局样式和复用图标，不并发改业务页面。
- 主任务负责领域授权与后续整合，迁移版本串行安排，不并发争抢 schema 版本。
- 子任务测试提交后 cherry-pick，主分支再运行回归；功能不完整时不标完成。

## 构建环境

使用已有 Java 8 / Maven 3.9.16（mise 安装目录），不修改全局工具设置；前端使用兼容 Vite 8 的 Node。
测试数据库全部位于临时目录，不对工作区运行数据执行迁移或写入。需要 UI 联调时启动独立测试实例并管理其后台作业，不能误改正在使用的实例。

源码事实与接口清单见 [实施方案](implementation-plan.md)。这是持续进度记录；方案中的“待确认”推荐现由自主实施基线统一取舍，有必要的兼容调整会记录在对应功能提交中。
