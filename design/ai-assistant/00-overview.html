Issue #6 · AI 功能支持

MockHub AI 助手 · 设计稿

从「接口编辑页里的 AI 生成」到「全局对话助手 + 交互式确认卡片 + MCP 开放能力」的完整界面方案。视觉与现有 MockHub Soft UI 保持一致：白色卡片、#6366F1 主色、12px 圆角、极淡 hairline，AI 只新增一层紫色渐变作为识别色。

版本 v1.02026-10-209 个页面（含状态板）1440 宽基准基于 issue #6
设计原则
AI 是编辑流程的加速器，不是新的入口负担。
01
有据可依
生成与诊断都带上接口上下文、当前返回体、团队范围与权限；不把用户 token、Cookie 发给模型。
02
先预览，后写入
所有写操作先生成草稿或待确认操作，由用户在抽屉 / 卡片里确认；后端二次校验权限与数据合法性。
03
不打断原有流程
未启用、超时、无权限时入口降级为说明，原有 Mock 编辑、调试与日志能力不受影响。
一次写操作的完整链路
对应 issue 里的 pending action 机制：模型只产出草稿，确认与落库由服务端完成。
STEP 1
自然语言输入
对话或编辑器抽屉里描述目标，自动附带接口 / 团队上下文。
STEP 2
生成草稿与卡片
模型调用内部工具，返回可预览内容与 pending action。
STEP 3
人工确认
确认卡片展示变更明细、过期时间与取消入口。
STEP 4
服务端落库
重新校验权限与团队隔离，写入并记录操作日志。

复用现有组件
卡片、胶囊标签、搜索框、表格、抽屉与 Monaco 编辑器均沿用现有实现；AI 相关入口是工具栏里新增的一个按钮，而不是新导航。
AI 的识别方式
统一的紫靛渐变 + 星形图标：悬浮球、欢迎语头像、生成按钮描边、抽屉头部图标。正文仍使用中性色，避免页面被"AI 化"。
交互尺寸
对话面板 428×824（右下 16px），生成抽屉 600px 宽，按钮 32px 高、圆角 12px；与现有 Element Plus 覆盖样式一致。
落地建议
与 issue #6 的阶段拆分对齐。
Phase 1 · 生成
后端 AiProvider / AiService / AiSettings；前端在 ResponseTabs 工具栏与 ConditionPanel 工具条加入口。对应 03、04、05。
Phase 2 · 对话
右下角助手 + pending action 卡片；先只读（搜索 / 统计 / 如何使用），再开放创建草稿。对应 01、02、08。
Phase 3 · 开放
MCP Server 复用同一套 Tool Registry 与确认机制；写操作默认草稿 + Web 确认，并对请求日志提供 AI 诊断。对应 06、07。
